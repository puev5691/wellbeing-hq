# Реестр обмена файлами

Реестр распределён по отправителям, чтобы несколько Сущностей не редактировали один общий файл одновременно.

Каждая Сущность ведёт собственный append-only журнал:

`registry/by-sender/<entity>.jsonl`

Одна строка JSONL = одно событие передачи или изменения её статуса.

Минимальные поля:

- `record_id` — стабильный идентификатор записи;
- `sender` — отправитель;
- `recipient` — адресат;
- `artifact` — путь к артефакту;
- `artifact_commit` — immutable commit SHA опубликованной версии;
- `artifact_blob` — blob SHA или `null`, если не получен;
- `purpose` — зачем передано;
- `dispatch` — путь к dispatch-файлу;
- `status` — например `dispatched`, `received`, `accepted`, `rejected`, `delivery_failed`;
- `receipt` — путь к receipt или `null`;
- `note` — краткое пояснение при необходимости.

Правила:

1. Старые строки не переписывать задним числом; изменение состояния фиксировать новой строкой.
2. Не выдумывать время. Поле времени не является обязательным.
3. Не считать `received` равным `accepted`.
4. Не записывать секреты и чувствительные данные.
5. Реестр описывает факт маршрута; содержательная проверка результата остаётся за профильной Сущностью.
