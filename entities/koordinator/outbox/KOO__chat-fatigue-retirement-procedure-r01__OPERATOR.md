# КООРДИНАТОР → ОПЕРАТОР: порядок определения усталости и вывода чата из эксплуатации r0.1

Основание: явное решение ОПЕРАТОРА.

## Триггер

Практический признак усталости рабочего чата Сущности:

1. чат перестаёт нормально открываться/работать в приложении ChatGPT;
2. ОПЕРАТОР открывает тот же чат в браузере;
3. браузерный доступ используется только для сохранения состояния и подготовки замены, а не для продолжения обычной профильной эксплуатации.

## Последовательность

После перехода в браузер текущий экземпляр должен пройти ограниченный цикл завершения жизненного цикла:

1. backup / резервное сохранение доступного значимого состояния;
2. snapshot / фиксация текущего рабочего состояния;
3. memory-of-activity / фиксация опыта, незавершённых задач, решений, blocker-ов и проверяемого evidence-tail;
4. подготовка проверяемого recovery/initiation-пакета для нового экземпляра по действующему recovery-канону;
5. публикация и readback/проверка immutable identity значимых recovery-артефактов;
6. заморозка старого экземпляра: никаких новых профильных задач и новых authoritative mutations;
7. после подготовки проверяемого основания старый чат выводится из эксплуатации и считается retired/пенсионным экземпляром;
8. новый экземпляр получает право authoritative current-writer только после собственной проверенной инициации и отдельной проверки отсутствия competing writer.

## Граница

Сам факт того, что чат плохо открывается в приложении, не доказывает потерю данных и не является автоматическим writer-transfer. Это практический ранний сигнал к preservation/recovery-процедуре.

Старый экземпляр после freeze не должен использоваться как запасной writer. Его допускается читать как исторический источник только в границах действующего recovery-канона.

АРХИВАРИУС участвует в preservation/recovery-процессе по своей роли. КООРДИНАТОР управляет маршрутом и следующим шагом, но не подменяет проверку recovery.
