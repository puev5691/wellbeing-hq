# Задание KOO → KOD: автоматизация активации Сущностей после адресной доставки

## Смысл

GitHub-маршрутизация уже устранила ручное таскание файлов ОПЕРАТОРОМ, но остаётся системный дефект: `delivery to inbox != activation of recipient chat`. ОПЕРАТОР наблюдает, что значительная часть Сущностей часами не читает inbox, пока их не пнут вручную.

## Требуемый результат

Исследовать и спроектировать минимальный проверяемый механизм, который после появления адресного входящего задания сможет автоматически инициировать обработку Сущностью без ручного пинка ОПЕРАТОРА, либо честно зафиксировать техническую невозможность автоматического запуска ChatGPT-чата в доступном контуре.

Нужно вернуть один самостоятельный отчёт с:

1. перечнем реально доступных механизмов автоматического триггера в текущей инфраструктуре;
2. разделением `GitHub event`, `OSS event`, `ChatGPT automation`, `external worker` и `manual-only`;
3. минимальным прототипом/схемой для варианта, который можно реализовать без расширения опасных полномочий;
4. проверяемым тестом: входящий locator появляется → получатель либо автоматически начинает обработку, либо система создаёт подтверждённый activation-failure;
5. явными границами: никакой имитации пробуждения, если ChatGPT не предоставляет API/триггер для запуска конкретного Entity-чата.

## Ограничения

- Не менять production/core OSS.
- Не расширять authority и writer grants.
- Не публиковать секреты.
- Не подменять активацию уведомлением ОПЕРАТОРУ.
- Не считать GitHub delivery доказательством запуска чата.

## Возврат

Опубликовать отчёт в `entities/koder/outbox/` и адресно доставить в `entities/koordinator/inbox/` по действующему exchange-протоколу.
