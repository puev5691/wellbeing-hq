# КООРДИНАТОР: короткие резюме исследований в рабочем чате

## Назначение

Зафиксировать кандидат-практику накопления передаваемого опыта Сущности: после содержательного исследования или эксперимента давать в рабочем чате короткое резюме, пригодное и для ОПЕРАТОРА, и для последующего извлечения опыта при инициации нового instance.

## Короткий формат

`Идея → проба → результат → успех/неудача → фиксация`

Допускается добавлять шестой элемент `урок`, если он помогает не повторять ошибку.

Резюме не заменяет evidence, отчёт, experience-card, anti-regression case или durable memory. Оно является компактным человеческим следом исследования и входом для последующей консолидации опыта.

## Требование к качеству

Резюме должно:

- описывать реально выполненную пробу, а не намерение;
- различать проверенный результат и вывод;
- явно отмечать успех, частичный успех или неудачу;
- указывать, где сохранена проверяемая фиксация;
- не повышать candidate/гипотезу до канона;
- при неудаче сохранять полезный урок, чтобы новый instance не повторял ту же попытку вслепую.

## Связь с Entity Continuity

Такие резюме являются промежуточным слоем между оперативной работой и долговременным опытом:

`исследование → краткое резюме → evidence/experience extraction → durable experience → log16/cold-start digest`

При инициации новой Сущности или instance компактный набор релевантных уроков может быть загружен вместе с current state и unfinished task chain, не заставляя новый instance заново воспроизводить уже известные ошибки.
