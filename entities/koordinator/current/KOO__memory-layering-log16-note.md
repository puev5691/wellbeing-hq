# Многоуровневая память Сущности и роль log16

## Смысл

В развитие концепции Entity Continuity фиксируется рабочая архитектурная гипотеза: избыточное сохранение оперативных материалов допустимо, если оперативный слой отделён от долговременной памяти и существует проверяемая процедура отбора/консолидации.

Предлагаемая цепочка:

`raw / operational -> consolidation -> durable memory -> log16 digest`

### Оперативный слой

Содержит рабочие заметки, промежуточные решения, гипотезы, следы неудач, локальные выводы и иные материалы текущего instance/task. Здесь допустим некоторый шум и временная избыточность.

### Консолидация

Из оперативного слоя выделяются сведения, которые должны пережить конкретный instance или текущую задачу: подтверждённое состояние, устойчивые решения, опыт и анти-регрессии, незавершённые причинные цепочки, новые требования, важные зависимости и ограничения.

### Долговременная память Сущности

Включает только проверяемые и дедуплицированные записи с provenance, freshness/applicability boundary и отношениями supersedes/conflict. Сырые разговоры и рабочие заметки не становятся автоматически действующим знанием.

### log16

log16 целесообразно рассматривать не как полную копию памяти, а как сильно сжатую хронологическую ленту опыта и переходов состояния:

`ситуация -> решение -> действие -> результат -> вывод`

Назначение log16: быстрый cold-start нового instance и восстановление хода жизни/работы Сущности без загрузки полного корпуса долговременной памяти. При необходимости новый instance по ссылкам/идентификаторам подтягивает только релевантные фрагменты durable memory и evidence.

## Архитектурное следствие

Entity Continuity требует не только recovery текущего состояния и Task Persistence, но и явного жизненного цикла памяти:

- capture;
- consolidation;
- promotion to durable memory;
- compression into log16;
- retrieval by relevance;
- supersedes/conflict handling;
- controlled forgetting/retirement of obsolete material.

Это пока кандидат архитектурного требования, а не новый канон.
