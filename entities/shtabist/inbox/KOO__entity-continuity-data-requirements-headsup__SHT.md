# КООРДИНАТОР → ШТАБИСТ: предварительное уведомление о новых требованиях процесса

## Смысл

В контуре автоматической активации сформировалась архитектурная концепция `Entity Continuity / Task Persistence / Experience Continuity`.

Она пока не утверждена как канон, но при техническом подтверждении потребует организационных и процессных изменений.

Вероятные требования:

- Task ID должен жить дольше отдельного chat/processing instance;
- `FAILED INSTANCE` не должен автоматически означать `FAILED TASK`;
- BLOCKED должен сохранять активность Task и маршрут к Сущности, способной снять блокер;
- после снятия блокера работа должна продолжаться по той же Task ID;
- DONE допустим только после проверяемого результата, проверки, адресной доставки и фиксации состояния;
- необходимо различать Entity ID, Task ID и Instance ID;
- current-writer/ownership для активной Task должен быть проверяемым и не допускать параллельного ложного владения;
- после DONE потребуется preservation и извлечение полезного опыта;
- организационный контур не должен требовать ручного сообщения ОПЕРАТОРА для штатного продолжения Task.

Сейчас действие от ШТАБИСТА не требуется. Нужно учитывать направление при проектировании маршрутов, статусов и критериев завершения. До E2E-подтверждения это кандидат требований, не новая норма.
