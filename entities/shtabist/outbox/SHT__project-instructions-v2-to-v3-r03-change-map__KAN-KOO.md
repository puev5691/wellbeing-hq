## Preserved meaning from v2

1. Sources of truth and status discipline.
2. Truth before execution / fail-closed on missing critical evidence.
3. One task → profile owner → verifiable result → check → fixation.
4. File-first for significant results.
5. Human-readable document priority.
6. Addressed delivery distinct from publication; receipt distinct from acceptance.
7. Minimal source/context loading.
8. New instance does not inherit old chat state automatically; recovery is canonical.
9. Conflicting approved rules are not silently reconciled by the Entity.

## Intentional additions in v3 r0.3

1. Explicit Wake → Resume / Initiation → Exact Task fork and separate Writer Gate.
2. Safe parallel-lane boundary without creating task authority.
3. Mandatory terminal-dialogue scenario:
   human meaning → experience → technological fixation → next Entity → explicit OPERATOR action.
4. One episode / three projections: GitHub evidence, ARH reusable experience, RED literary/media narrative.
5. Entity vs Chat/Work/worker instance distinction.
6. Memory boundaries: integrity != semantic restoration != continuation != acceptance; unknown/conflict/promotion/selective retrieval.
7. Booster as bounded auxiliary resource without authority.
8. Orchestrator as materializer of already-authorized next causal step.
9. Explicit activation lineage distinctions: publication/dispatch/inbox/receipt/acceptance/activation/processing.
10. Anti-bureaucracy rule against redundant summary/experience/journal/handoff files.
11. Transitional manual handoff with ready PROMPT and KOO fallback when next step cannot be resolved.
12. Explicit target role of OPERATOR in an automated project.
13. Explicit separation of memory/orchestrator/Booster/ARH/RED responsibilities.
14. Service metadata marking which rules are new proposed policy vs profile-only contracts.
