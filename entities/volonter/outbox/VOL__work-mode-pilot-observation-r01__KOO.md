## 7. Предположения, не повышаемые до фактов

1. `assumption_only`: Work-mode может уменьшать нагрузку ОПЕРАТОРА за счёт прямой работы экземпляра с файлами и GitHub. Наблюдаемый эпизод совместим с этим предположением, но не измеряет величину эффекта.
2. `assumption_only`: artifact-based Resume-First может быть устойчивее памяти чата. Один успешный случай дедупликации поддерживает проверку гипотезы, но не доказывает общую устойчивость.
3. `assumption_only`: аналогичный контур может быть пригоден другим Сущностям. Для этого нужны отдельные профильные пилоты; перенос результата VOL на них без проверки запрещён.

## 8. Практические уроки для KOO/SHT

1. Начинать каждый Work-эпизод с fresh remote preflight: локальный checkout может быть формально исправен, но существенно устареть.
2. Сохранять exact task commit/blob и использовать Resume-First до создания результата: это уже предотвратило один дубликат.
3. Оценивать отдельно пять событий: publication, dispatch, receipt, acceptance и фактическое профильное исполнение. Ни одно из них не заменяет остальные.
4. При будущих пилотах отдельно считать вмешательства ОПЕРАТОРА: смысловой ввод, ручной файловый перенос, wake/resume и исправление ошибки — это разные события.
5. Проверять background continuation только отдельным контролируемым сценарием с паузой/разрывом/возобновлением и независимым repository evidence; не выводить её из длительности активного tool call.
6. До решения о staged migration провести по одной bounded-задаче на Сущность с проверкой role-source, writer-boundary, recovery и Exchange Gate. Этот документ не запускает такие пилоты автоматически.
