# DEDUP / VARIANTS v0.1

## Метод и ограничение

File Library в текущем интерфейсе отдаёт file identity и извлечённый текст, но не сырые bytes. Поэтому:
- `exact duplicate by bytes` в этом проходе **не подтверждается**, если файл не был локально получен;
- `near duplicate / likely exact text duplicate` ставится только там, где независимые File Library identities возвращают одинаковое название и совпадающие извлечённые фрагменты/структуру;
- разница времени загрузки или filename сама по себе не считается новой редакцией.

## Найденные пары

### DEDUP-001 — «Что такое организационные технологии»
- `file_00000000dfe081f69680adf167763cd9`
- `file_00000000435c81f58be5714805284530`
- Статус: `near_duplicate_likely_text_exact`
- Основание: совпадают заголовок, начальные определения, структура разделов и извлечённые фрагменты.
- Byte equality: `unknown`.
- Действие registry: оба сохраняются как provenance; один не считать отдельным тезисным источником.

### DEDUP-002 — «О формировании коллективного/общественного субъекта»
- `file_00000000c43081f5bc60ce8d6dd360f5`
- `file_000000004858822fb1a118aa9e55b183`
- Статус: `near_duplicate_likely_text_exact`
- Основание: одинаковый заголовок и совпадающие последовательные фрагменты, включая схему «индивиды → взаимодействие → совместная деятельность → общие интересы → коллектив → сообщество → народ».
- Byte equality: `unknown`.

- `file_0000000025a481f5a6cca0dcab7b096c`

- Замечание: один экземпляр загружен раньше; metadata upload time не доказывает редакционную хронологию.

## Ранее обнаруженные в корпусе пары, требующие повторной регистрации при появлении в устойчивом corpus store

По текущему рабочему контексту были замечены повторные загрузки:
- «Как отчуждённый труд создаёт своего могильщика»;
- «Семь столпов в логике барыг»;
- «Откуда берутся миллиардеры»;
- вариант/повтор «О формировании коллективного/общественного субъекта».

В этом v0.1 в formal registry включены только те пары, которые заново подтверждены текущим File Library retrieval.

## Рекомендация для следующего прохода

Когда КООРДИНАТОР/АРХИВАРИУС создаст canonical corpus storage:
1. сохранить исходные bytes без редактирования;
2. считать SHA-256;
3. exact duplicates объединять логически, не уничтожая origin records;
4. для DOCX дополнительно считать hash нормализованного текста, чтобы отделить форматные изменения от содержательных;
5. variants сравнивать по section/paragraph diff.
