# Библиотека ВЕБМАСТЕРА: современный веб и автоматизация публикаций

## Назначение

Рабочая библиотека ВЕБМАСТЕРА для подготовки к активной работе в медийном контуре проекта «ШТАБ БЛАГОПОЛУЧИЯ».

Это не новый Project Source и не утверждённая архитектура production. Здесь собраны проверенные внешние сведения, практические выводы и кандидаты для последующих пилотов.

## Короткий вывод

Наиболее перспективная для проекта схема выглядит так:

`Markdown/данные в Git -> проверка схемы -> preview -> quality gates -> approval -> production deploy -> readback -> Atom/WebSub -> адаптеры Telegram/других площадок -> журнал результата`

Ключевой принцип: **сайт остаётся каноническим источником публикации**, а внешние каналы получают производное представление через отдельный слой синдикации. Так веб-слой не связывается намертво с Telegram, конкретным CMS или одной хостинговой платформой.

## Состав

- `MODERN-WEBMASTERING.md` — современная модель работы ВЕБМАСТЕРА и технологический радар.
- `PUBLICATION-AUTOMATION.md` — конвейер автоматической публикации, проверки и отката.
- `MEDIA-CONTOUR.md` — интеграция сайта с Telegram, feeds, WebSub, n8n и будущими каналами.
- `SOURCE-REGISTRY.md` — реестр использованных внешних источников и их назначение.
- `PILOT-BACKLOG.md` — безопасные read-only/standalone пилоты без вмешательства в текущий production.

## Что рекомендовано исследовать первым

1. Фактический аудит существующего сайта и публикационного слоя.
2. Отдельный prototype-репозиторий с одной публикацией в Markdown.
3. Автосборка preview через GitHub Actions.
4. Автоматические проверки ссылок, HTML, доступности и Lighthouse CI.
5. Генерация Atom feed и sitemap.
6. Post-publish адаптер Telegram только после успешного readback опубликованной страницы.

## Что пока не утверждается

Не утверждается, что проекту уже нужен Astro, Cloudflare Workers, Decap CMS, n8n, ActivityPub или любая другая технология из библиотеки. Это кандидаты. Выбор должен быть сделан после read-only аудита фактического контура и оценки ограничений.
