## Решение ОПЕРАТОРА

Текущий WBN-эксперимент считается первым исследовательским запуском и может быть завершён.

Выявленная архитектурная ошибка для дальнейшей программы: весь текущий кластер был запущен в режиме шарда. Такой контур не должен становиться основой будущей сети.

Следующий основной эксперимент должен начинаться с нового генезиса как основной кластер / корневая цепь. В дальнейшем именно этот основной кластер должен служить корнем для подключения и испытаний шардов.

## Что это меняет

1. Текущий fork Буржуиния ↔ эРэФия больше не требуется лечить ради продолжения этой экспериментальной цепи.
2. Старую WBN-историю нельзя автоматически переносить в новый основной кластер как canonical history.
3. Перед завершением старого эксперимента сохраняется только необходимая исследовательская ценность: точные конфиги, chain identity, точка fork, проверенные результаты и при необходимости архивные snapshots.
4. Новый эксперимент проектируется отдельно от старого DATA/DB и начинается с нового генезиса.
5. Первый критерий нового запуска: несколько узлов должны образовать одну основную цепь с одинаковой genesis identity, совпадающими контрольными блоками и реальной peer-связностью.
6. Только после устойчивого основного кластера начинается отдельная фаза создания и подключения первого шарда к этому корню.

## Рабочая последовательность

Фаза A — корректное завершение первого эксперимента:
- зафиксировать минимальный recovery/research package старой WBN;
- определить, нужны ли полные snapshots DATA/DB обеих разошедшихся веток или достаточно конфигурационных и контрольных артефактов;
- после отдельного разрешения ОПЕРАТОРА остановить старые WBN runtime-процессы без удаления данных.

Фаза B — исследование точного механизма main/root genesis в TERA2:
- проверить upstream-код и документацию, чем основной genesis-контур отличается от shard mode;
- определить минимальный набор файлов и параметров genesis identity;
- исключить наследование старого `DATA/shard.js` как механизма запуска основной цепи, если upstream это подтверждает;
- подготовить воспроизводимый deployment-пакет и проверку chain identity.

Фаза C — чистый запуск основного кластера:
- развернуть новый runtime в отдельном каталоге, не поверх старой WBN DB;
- создать genesis основного кластера;
- запустить первый узел;
- подключить второй узел и подтвердить одинаковую цепь;
- подключить третий узел и подтвердить одинаковую цепь;
- проверить peer graph, block hashes, state/account consistency, restart/recovery.

Фаза D — первый настоящий shard experiment:
- только после PASS основного кластера;
- создать отдельный shard с собственной shard identity;
- подключить его к основному кластеру как к корню;
- проверить bootstrap, обмен состоянием/операциями и failure/recovery сценарии.

## Стоп-условия

До завершения Фазы B нельзя считать известным точный способ запуска root/main genesis в TERA2 только по старому эксперименту: текущий опыт относится к shard mode.

Никакие старые DATA/DB не удаляются и текущие WBN-сервисы не останавливаются автоматически этой записью. Для runtime/data mutation требуется отдельный проверяемый шаг.

## Цель следующего исследования

Получить проверяемый ответ на один вопрос: как именно в текущем upstream TERA2 воспроизводимо создать и запустить основной genesis-кластер, который затем может быть корнем для шардов.
