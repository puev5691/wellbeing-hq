# Непрерывная специализированная Сущность поверх сменяемых экземпляров

## Смысл

Эксперимент с автоматической активацией вывел задачу за пределы первоначального «разбудить существующий чат».

Архитектурная цель: **непрерывность деятельности долговечной специализированной Сущности поверх сменяемых processing/chat instances**.

Отдельный экземпляр может завершиться, исчерпать контекст, упасть или быть заменён. Это не должно уничтожать идентичность Сущности, накопленный проверенный опыт или принятую незавершённую задачу.

## Три идентичности

- **Entity ID** — долговечная Сущность: роль, канон, состояние, накопленный опыт.
- **Task ID** — принятая цель, живущая до проверяемого завершения или явного прекращения уполномоченной Сущностью.
- **Instance ID** — сменяемый вычислительный экземпляр.

Инвариант:

> Принятая задача остаётся активной до проверяемого DONE либо явного решения о прекращении. Смерть, timeout, ошибка или исчерпание контекста instance задачу не завершают.

## Цикл деятельности

`addressed event → detector → supervisor → recovery → initiation → current-state restore → relevant experience restore → unfinished-chain restore → processing instance → work → verification`

Экземпляр получает три слоя: **канон**, **текущее состояние**, **рабочий опыт**. Контекстное окно становится оперативной памятью экземпляра, а не единственным носителем опыта Сущности.

## Удержание Task

**DONE:** результат проверен и адресно доставлен; состояние сохранено; полезный опыт извлечён.

**BLOCKED:** конкретный внешний блокер адресован способной снять его Сущности; Task остаётся активной; после проверяемого снятия supervisor продолжает ту же Task ID.

**FAILED INSTANCE:** состояние/evidence экземпляра сохранены; Task остаётся незавершённой; supervisor запускает следующий instance с recovery.

`FAILED INSTANCE != FAILED TASK`.

## Supervisor

`activation-worker` развивается в **Entity supervisor**: обнаруживает событие, проверяет immutable provenance и Exchange Gate, определяет Entity/Task, проверяет recovery/current-writer state, инициирует instance, восстанавливает контекст/опыт, удерживает Task, обрабатывает BLOCKED/instance failure и запускает preservation/experience extraction.

Supervisor не расширяет authority/writer grants и не выдаёт новый instance за прежний current-writer.

## Накопительное обучение и рефлексивный цикл

Непрерывность создаёт возможность не только помнить решения, но и **сопоставлять наблюдения из разных эпизодов и задач**, которые раньше не встречались в одном контекстном окне.

Рабочий цикл:

`накопленный опыт → новая комбинация наблюдений → гипотеза → эксперимент/проверка → результат → обновлённый опыт`.

Дополнительно нужен периодический рефлексивный цикл:

`experience corpus → поиск повторяющихся структур/аномалий → сопоставление удалённых эпизодов → кандидат закономерности → проверка → новая концепция`.

Это создаёт функциональные условия для появления новых гипотез и неожиданных переносов опыта. Такие результаты можно бытовым языком сравнивать с «озарением», но архитектура сама по себе **не доказывает сознание или человеческое мышление**.

Чтобы накопление не превращалось в склад красивых заблуждений, кандидат знания проходит состояния:

`наблюдение → гипотеза → проверка → подтверждено | опровергнуто | ограничена область применимости`.

Для этого критичны evidence, confidence, freshness, applicability boundary и supersedes.

## Что именно развивается

LLM остаётся сменяемым когнитивным механизмом. Развивающейся системой становится **Сущность целиком**: её Entity ID, состояние, история задач, проверенный опыт, концепции и процедуры проверки.

Следующая инстанция может работать на другой модели или частично специализированном коде, сохраняя проверяемую преемственность Entity.

## Целевой E2E

`адресная задача`
→ без сообщения ОПЕРАТОРА определена Entity
→ создан instance
→ проверены идентичность и authority boundary
→ восстановлены состояние, незавершённая цепочка и релевантный опыт
→ Task выполнена или корректно BLOCKED
→ при необходимости продолжена следующим instance
→ результат проверен и доставлен
→ новое состояние и опыт сохранены
→ новый опыт доступен последующим рабочим и рефлексивным циклам.

Недостаточно доказать один `processing_started`: нужен полный контур **Entity Continuity / Task Persistence / Experience Continuity / Reflective Learning**.

## Цена и риски

Нужны recovery/state preservation, experience extraction/ingest, дедупликация/supersedes, freshness/applicability boundary, causal/task-chain restoration, контроль противоречий и ложного current-writer inheritance, а также управление стоимостью cold start и объёмом контекста.
