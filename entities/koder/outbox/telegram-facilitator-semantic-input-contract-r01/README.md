# Смысловой вход для ядра обсуждений r0.1

Библиотека принимает отдельно допущенный минимизированный фрагмент или структурированное утверждение, проверяет его контракт и создаёт `NormalizedEvent` принятого ядра. Это **не обработчик Telegram и не автоматический анализатор текста**. Перед реальным подключением требуются независимая проверка и отдельный доверенный механизм минимизации/допуска.

## Запуск и состав

Локальный Python 3.10+ под обычным пользователем, без сети и секретов. В операторском архиве находятся `candidate/` и `deps/`; установка пакетов и служб не нужна.

```sh
python3 -I -B candidate/test_semantic.py --core deps/facilitator_core.py
```

`semantic_input.py` содержит схему и преобразование, `fixtures.py` создаёт учебный поток из 13 входов, `test_semantic.py` проверяет контракт и интеграцию. Фактические stdout/stderr и MANIFEST включены в пакет. В GitHub зависимость не дублируется: её точные путь, commit, blob и SHA-256 приведены в MANIFEST.

Ядро загружается из проверенных байтов `facilitator_core.py`, commit `0020dff62785a5fd0048b0696728b3518812dcd1`, blob `ad980b0de8a00c1d134823cebc49059a0811f3fa`. Других зависимостей, кроме стандартной библиотеки, нет.

## Граница относительно Phase 1B

Существующая `safe_receipt` намеренно содержит только агрегатные данные. Новая библиотека не извлекает из неё отсутствующие текст, проблему или позиции. Семантические входы должен предоставить **будущий отдельный privacy gate**, то есть механизм проверки допустимости и минимизации данных. Код получения настоящих сообщений и реализация этого механизма не входят в пакет.

Поток:
`допустимая минимизированная проекция → отдельное подтверждение допуска → SemanticAdapter.convert → NormalizedEvent → отдельный вызов ядра → отдельное рассмотрение кандидатов`.

Принятые Phase 1B, агрегатный мост и ядро не изменяются. Допуск к преобразованию не разрешает публикацию, отправку или исполнение задач.

## Явная схема SemanticInput

`parse(bytes)` разбирает JSON закрытого состава в неизменяемый `SemanticInput`. `SemanticAdapter.convert` принимает только байты и повторяет всю проверку. Ручное создание Python-объекта само по себе не даёт допуска. Это прикладная схема Python/JSON, не заявление о соответствии отдельному стандарту JSON Schema.

| Поле | Значение |
| --- | --- |
| `schema_version` | Только `semantic-input-r01`. |
| `input_id` | `semantic_` и 32 шестнадцатеричных символа. |
| `content_class` | `synthetic` либо `admitted_minimized`. Локальные значения схемы, не новая классификация всего проекта. |
| `purpose` | Только `discussion_facilitation`. |
| `scope` | Ровно `discussion_id`, `event_id`, `sequence`, `at_tick`. |
| `content` | Ограниченный excerpt либо claim; состав описан ниже. |
| `category` | Одна явно объявленная категория из разрешённой политики анализа. |
| `targets` | Список явных event_id, только для разногласия. |
| `disagreement_level` | Явный уровень разногласия либо null. |
| `participant` | null либо ограниченная обсуждением псевдонимная ссылка. Поле обязательно, значение может отсутствовать. |
| `content_source_id` | Ссылка на источник именно минимизированного содержимого. |
| `sources` | От 1 до 8 источников с собственными политиками. |
| `policy` | Политика самого смыслового входа. |
| `analysis_policy` | Явно заданная политика использования категории и текста. |
| `authority` | Точные task/writer/privacy_gate и область допуска. |

Неизвестные или отсутствующие поля отклоняются, включая вложенные объекты. Повторные JSON-ключи, NaN, некорректный Unicode и необъявленные Telegram/user/credential/action поля запрещены. Общий вход ограничен 16384 байтами.

### Содержимое и категории

Для фрагмента: ровно `kind="excerpt"` и `text`. Текст непустой, содержит не более 512 байт UTF-8 или меньшего лимита политики. Переводы строк и управляющие символы не поддерживаются. Обрезки и скрытой замены текста нет.

Для утверждения: ровно `kind="claim"`, `subject`, `predicate`, `object`. Каждая строка непустая, до 160 байт; итоговое представление `subject | predicate | object` также укладывается в лимит политики. Это форматирование заявленного утверждения, не логический вывод, подтверждение факта или извлечение из сырого сообщения.

Категории совпадают с принятым ядром: topic, problem, concept, fact_claim, goal, criterion, option, procedure, position, preliminary_agreement, open_question, disagreement.

`analysis_policy` имеет ровно `mode`, `source`, `allowed_categories`, `max_text_bytes`, `allow_participant`. В первой версии поддерживается **только declared_only**: категория сообщена входным контуром. Даже разрешённая общим списком категория должна входить в явный непустой allowlist этой политики. Дубликаты и неизвестные категории запрещены. `source` является точной ссылкой ArtifactRef. Производные, эвристические и LLM-категории отклоняются как `BLOCKED_SEMANTIC_ANALYSIS_UNSUPPORTED`, а не включаются одним изменением флага.

Политика анализа и категория входят в точный отпечаток допуска. Они не получают полномочия только потому, что присутствуют в JSON.

Разногласие требует минимум двух различных явных targets, не ссылающихся на текущее событие, и одного уровня facts/concepts/goals/criteria/means/procedure/other. Максимум targets: 16. Другие категории не имеют targets/level. Существование целевых событий и запрет вложенного разногласия проверяет прежнее ядро при отдельном `apply_event`. Библиотека состояния обсуждения не читает.

### Область и источники

 discussion_id, event_id, source_id имеют соответствующий префикс плюс 32 шестнадцатеричных символа. sequence положительное целое, at_tick неотрицательное; локальный предел `2**53-1`. Boolean не считается числом.

Источник имеет ровно `scope`, `source_id`, `version_sha256`, `kind`, `policy`. Все scope совпадают с обсуждением; source_id уникальны. `content_source_id` выбирает ровно один источник. Его SHA-256 должен совпасть с каноническим JSON **допущенного минимизированного content**, не сырого исходного сообщения. Канонизация: UTF-8, сортировка ключей, разделители без пробелов, без NaN.

Исходные ссылки сохраняют порядок и поля при преобразовании. Их политики объединяются в выходную политику. Добавляется одна ссылка на точный SemanticInput: `source_` с суффиксом input_id и SHA-256 типизированного объекта `asdict(SemanticInput)`. Коллизия с исходной ссылкой запрещена. Благодаря этой связи изменение категории, политики, полномочий или участника меняет происхождение события, даже если сам текст прежний.

SHA-256 подтверждает совпадение, но не достоверность утверждения, подлинность источника, анонимность или право хранения. Разрешённая проекция может существовать только в памяти входного контура; постоянный архив исходных сообщений не требуется.

### Псевдонимная ссылка участника

`participant` содержит ровно `scope`, `pseudonym`, `expires_tick`, `scheme`. Допустимы только текущий discussion_id, `participant_` плюс 32 шестнадцатеричных символа и `scheme="discussion_local_opaque"`. Политика должна разрешать participant; внешний проверяющий должен отдельно подтвердить ограниченность ссылки обсуждением.

Библиотека не принимает Telegram user_id/username, не создаёт псевдонимы и не требует таблицы их постоянного соответствия людям. Она **не способна определить по строке**, получен ли псевдоним хешированием user_id или связывает ли он разные обсуждения. Это обязанность входного механизма. Такой псевдоним не объявляется анонимизацией.

Прямая ссылка участника не копируется в NormalizedEvent или SemanticResult; она включена в отпечаток SemanticInput. Срок выходных производных ограничен также её expires_tick. Установить согласие группы или число уникальных людей по этой ссылке библиотека не пытается.

## Приватность, сроки и хранение

Каждая `policy` имеет ровно `privacy_class`, `retention_class`, `expires_tick`. Для `synthetic` допустимы `memory_only` или `synthetic_snapshot`. Для `minimized_derived` допустим только `memory_only`.

Синтетический вход не может ссылаться на минимизированный несинтетический источник. Для admitted_minimized вход и источник его содержимого должны иметь minimized_derived; дополнительные синтетические источники допустимы. kind соответствует собственной политике: synthetic_fixture либо normalized_projection.

Выход наследует наиболее строгие классы и ближайший expires_tick входа, всех источников и участника. Переданный отдельно `now_tick` должен быть не раньше at_tick и строго раньше каждого обязательного срока. Старой отметкой at_tick нельзя скрыть просрочку на момент преобразования. Отдельный допуск также ограничивает максимум хранения.

Это логическое время, не секунды и не проектная временная метка. Доверенные часы и смысл шкалы задаёт внешний контур. Входной допуск действует в момент преобразования; последующее использование должно соблюдать исходный срок и отзыв допуска.

Модуль не пишет журналы, файлы, БД или raw storage. Core.snapshot запрещён для minimized_derived/memory_only. Истечение срока создаёт проекцию без просроченных элементов; физическое уничтожение старых Python-объектов, памяти, swap, чужих журналов и копий не обещается. Свободный `asdict` в доверенном вызывающем коде не является разрешением сохранять результат.

**Метка минимизации не доказывает очистку.** Переименование raw text в excerpt ничего не разрешает. Автоматического распознавания персональных данных внутри строки в этой библиотеке нет; нужен отдельно проверенный механизм минимизации и подлинный допуск к точным байтам.

## Полномочия и AdmissionProof

`authority`: ровно `requester_id`, `task`, `writer`, `privacy_gate`, `scope`. requester_id содержит от 2 до 16 прописных латинских букв/цифр; scope только `semantic_input_to_observe_only`.

ArtifactRef содержит ровно `repository`, `path`, `commit`, `blob`. Требуются точные 40-символьные Git SHA, не имя ветки. Пути не содержат пустых сегментов, `.` или `..`.

`convert(data, now_tick=..., verifier=None)` закрыт без внешнего verifier. Проверяющему передаётся неизменяемый AdmissionCheck: SHA-256 смыслового входа, authority, политики анализа, content, полного списка источников, participant, а также обсуждение, цель, категория, класс и эффективная политика. Свободный текст или псевдоним проверяющему не копируются; он должен проверить связанные источники в своём разрешённом контуре.

Verifier возвращает точный AdmissionProof, а не True: check_sha256, source, valid_from_tick, valid_until_tick, retention_limit_tick, minimization_confirmed, participant_scoped_confirmed, scope. Условия подтверждения проверяются буквально, время и предел хранения проверяются отдельно. Контекст повторно сверяется после callback.

Подлинность proof/source, актуальность task/writer, минимизация, происхождение категории и допустимость псевдонима являются обязательствами **доверенного внешнего verifier**. Этот пакет его не реализует. Учебные ссылки synthetic-fixture и функция exact_verifier в тесте не дают права на реальные данные.

## Выход и проверка

SemanticResult содержит событие точного типа принятого ядра, отпечатки входа/проверки/допуска/события, отдельные authority/proof_source/analysis_policy. Его `redacted()` не содержит текст и псевдоним. Постоянные границы: `project_acceptance=NOT_GRANTED`, `dispatch_performed=false`, `executable_task_created=false`.

Библиотека только конвертирует. В интеграционном тесте вызывающий тестовый код отдельно запускает ядро и синтез. На 13 смысловых входах и отдельном событии synthesize получены 13 элементов обсуждения, два вопроса, одна сводка и один кандидат задачи. Даже approve/reject/defer отдельного рассмотрения не дают кандидату права исполнения.

Выполнены 39 тестовых методов. Контроль операций устанавливается до импорта кандидата и запрещает сеть, процессы, записи, открытие SQLite и недопустимые чтения. Проверены неправильные типы, закрытая схема, пределы UTF-8, все категории, source/content mismatch, связность допуска, приватность, сроки, участник, детерминизм и границы ядра. Кандидат рассчитан на доверенный Python-процесс, не на противодействие злонамеренной подмене интерпретатора, модулей или verifier.

Следующий этап: независимая проверка точного пакета. Получение реального текста, его минимизация, реальная авторизация, хранение, публикация и развёртывание требуют отдельных решений. Откат сервисов не требуется: сервисы не изменялись.
