# Мост агрегатной квитанции Phase 1B → NormalizedEvent r0.1

Пакет преобразует существующую минимизированную квитанцию `Gateway.safe_receipt()` в один `NormalizedEvent` принятого ядра. Нужны независимая проверка и отдельный допуск к реальному подключению. Пакет не понимает содержание сообщений, не создаёт исполняемых задач и не меняет Phase 1B.

## Где именно проходит граница

Поддерживаемый производитель: `telegram-media-phase1b-threading-fix-r02/gateway.py`, commit `62f82c3322f28adc55b47b1a7064fccb23e4c351`, blob `c870616f119fa3198a50db31898ad9ba4ad4bafc`. Это независимо проверенная линия с сохранённым режимом `aggregate_only`.

Вызов `safe_receipt(publication_id, distribution_target)` возвращает идентификаторы доставки, счётчики и защитные признаки. `ingest_update()` не выдаёт смысловое событие обсуждения, а HTTP-обработчик возвращает только служебный исход. Поэтому мост принимает именно результат `safe_receipt`, не raw Telegram update и не HTTP-ответ webhook.

`safe_receipt` не содержит полномочий вызывающей Сущности, области события и срока для нового производного. Они задаются отдельным обязательным контекстом. Квитанция без него отклоняется. Контекст не объявляется уже существующим выходом runtime: это входной контракт нового изолированного адаптера.

Точка будущего подключения: разрешённая агрегатная квитанция → проверенный внешний контекст и допуск → `Bridge.convert()` → `BridgeResult.event` → отдельный вызов принятого ядра → отдельное рассмотрение кандидатов. Код подключения, опроса БД и изменения службы не создаётся.

## Запуск

Локальный Python 3.10+ под обычным пользователем, без сети и секретов. Установка пакетов не нужна. В операторском архиве находятся каталоги `candidate/` и `deps/`.

```sh
python3 -I -B candidate/test_bridge.py --deps deps
```

В репозитории зависимости не дублируются. Их точные пути, commits и контрольные суммы находятся в MANIFEST. `phase1b_gateway.py` в `deps` является переименованной копией исходного `gateway.py` без изменения байтов; он нужен только тесту. В рабочем преобразовании требуется только точное `facilitator_core.py`.

В тесте вызывается неизменённый метод `safe_receipt`, но его источник строки заменён синтетическим объектом в памяти. Конструктор `Gateway`, SQLite connection, Telegram transport и службы не запускаются. Следовательно, тест проверяет форму реального метода, а не состояние установленного runtime.

## Явная схема входа

Машинная проверка схемы реализована в `strict_json`, `closed`, `ArtifactRef` и `Bridge.convert`. Это локальная закрытая схема, не заявление о реализации стандарта JSON Schema. Неизвестные и отсутствующие поля отклоняются на всех описанных уровнях. Общий размер входа: 1–16384 байта UTF-8; повторные ключи, NaN и повреждённый Unicode запрещены.

| Обязательное поле верхнего уровня | Контракт |
| --- | --- |
| `schema_version` | Только `phase1b-safe-receipt-bridge-r01`. |
| `producer_blob` | Точный blob поддерживаемого `gateway.py`; само поле не удостоверяет производителя. |
| `receipt` | Ровно 13 полей существующего `safe_receipt`, перечисленных ниже. |
| `receipt_source_id` | Идентификатор ровно одного элемента `sources`, описывающего эту квитанцию. |
| `event_context` | Ровно `discussion_id`, `event_id`, `sequence`, `at_tick`. |
| `data_class` | `synthetic` либо `phase1b_aggregate_minimized`. Это локальные значения данной схемы, не новая обще-проектная классификация. |
| `policy` | Ровно `privacy_class`, `retention_class`, `expires_tick`. |
| `sources` | От 1 до 8 разрешённых ссылок; каждый элемент имеет `scope`, `source_id`, `version_sha256`, `kind`. |
| `authority` | Ровно `requester_id`, `task`, `writer`, `decision`, `scope`. |

### Квитанция

`publication_id` и `distribution_target`: непустые ASCII-ключи до 128 символов, алфавит букв, цифр, `_ . : -`; первый символ буква или цифра. Это консервативное ограничение нового адаптера. Более широкий вход, принимаемый старым gateway, не обязательно поддерживается мостом.

`external_chat_id`: ненулевое целое от `-(2**53-1)` до `2**53-1`; `external_message_id`: целое от 1 до `2**53-1`. Это технические идентификаторы канала/сообщения, не audience identity. Boolean не считается целым.

`delivery_state`: только `delivered_verified`. Это проверка технической доставки, не полномочие на обработку и не содержательная приёмка.

`comments_count`, `reaction_total`: целые от 0 до 10**9. `member_count`: такой же диапазон либо null. Null сохраняется как неизвестное значение и не превращается в ноль. Границы локальные, не лимиты Telegram.

`personal_data_exported`, `raw_comment_exported`, `production_publication`: только буквальное false. `privacy_mode`: `aggregate_only`. `privacy_policy_marker`: точная строка поддерживаемого производителя, закреплённая в коде.

### Идентичность, происхождение и срок

`discussion_id`, `event_id`, `source_id` имеют соответствующий префикс плюс 32 шестнадцатеричных символа. Их предоставляет контролируемая сторона, не мост; они не выводятся из пользователя или сырого текста. `sequence` положительное целое; `at_tick` неотрицательное целое; предел обоих `2**53-1`.

Все `sources.scope` совпадают с discussion_id. source_id не повторяется. `version_sha256` содержит 64 шестнадцатеричных символа. У ссылки, выбранной `receipt_source_id`, он обязан совпасть с SHA-256 канонического JSON всей разрешённой квитанции: ключи сортированы, UTF-8, без пробелов-разделителей. Мост сохраняет все ссылки и их порядок. Изменение счётчика или технической идентичности меняет отпечаток. Это отпечаток разрешённой проекции, не audience-linking hash.

Для `synthetic`: privacy_class=`synthetic`, source.kind=`synthetic_fixture`, retention_class=`memory_only` или `synthetic_snapshot`. Для `phase1b_aggregate_minimized`: privacy_class=`minimized_derived`, source.kind=`normalized_projection`, только `memory_only`. Источник и класс проверяются совместно; неизвестные классы и понижение приватности запрещены.

`expires_tick` строго больше at_tick и не превышает лимит, подтверждённый внешним допуском. Выход получает ту же политику, без увеличения срока. Логические отметки не являются секундами или проектным временем. Подключающий контур обязан согласовать их с реальными сроками и существующим правилом очистки Phase 1B. Мост не подставляет 30 дней автоматически и не стирает старые объекты, память или внешние копии.

### Полномочия

requester_id: от 2 до 16 прописных латинских букв/цифр, начинается буквой. `task`, `writer`, `decision` имеют ровно `repository`, `path`, `commit`, `blob`. Branch name вместо 40-символьного Git SHA запрещён. Пустые сегменты пути, `.` и `..` запрещены.

`authority.scope` только `convert_aggregate_receipt_to_fact_claim`. Публикация, согласование задач и исполнение не входят в эту область.

Переданное поле decision само себя не утверждает. `Bridge.convert(data, verifier=None)` закрыт по умолчанию. Доверенная внешняя функция получает неизменяемый `AdmissionRequest` и должна вернуть `Grant`, совпадающий с SHA-256 всего запроса, полномочий и классом данных, с действительным временным окном и верхним пределом хранения. Boolean True вместо Grant недостаточно.

Внешняя функция обязана отдельно проверить действующий writer/task, происхождение квитанции, допустимость области обсуждения, подлинность ссылок, очистку метаданных и срок. Тестовая функция одобрения фиксированных синтетических байтов не является реальной авторизацией. Защита от злонамеренной замены Python-кода или ложного verifier не заявляется.

## Выход и его границы

`BridgeResult.event` имеет точный тип принятого ядра, загружаемого по blob и SHA-256. Действие всегда `observe`, категория всегда `fact_claim`, targets пусты, disagreement_level отсутствует. Текст строится только из трёх счётчиков и указания отсутствия содержания обсуждения. Произвольная строка из квитанции туда не копируется.

Нельзя восстановить из агрегатов проблему, цели, позиции, причины разногласий или согласие участников. Мост этого не делает. `fact_claim` в ядре означает учтённое сообщение о состоянии, не удостоверенную истину о группе.

Идентичность источника и политика сохраняются в NormalizedEvent. Task/writer/decision остаются отдельным происхождением BridgeResult: формат принятого ядра ими не расширяется. Технические publication/target/chat/message IDs не копируются в результат; их разрешённая проекция связана SHA-256. Реальная доступность locator остаётся обязанностью входного контура.

Сам мост не вызывает apply_event, synthesize, record_decision или dispatch. Состояние изменяет отдельный вызывающий код. В интеграционных тестах агрегаты сами по себе не создают задачу; при наличии отдельно заданной проблемы и цели созданный ядром кандидат остаётся candidate_only даже после отдельной записи approve.

Модуль не имеет собственного хранения или журналирования. core.snapshot закрыт для minimized_derived. Это не запрет произвольному доверенному Python-коду скопировать объект через asdict: такой код обязан соблюдать отдельный режим хранения и не считать наличие метода сериализации разрешением.

## Что ещё требуется перед реальным подключением

Независимая проверка точных байтов, отдельно проверяемый источник квитанции и контекста, реализация доверенного verifier, привязка логических сроков к действующему retention-контракту и отдельный допуск к месту вызова. Принятые Phase 1B и facilitator-core не меняются. Семантический анализ сообщений потребовал бы другого входного/privacy-контракта, которого этот пакет не создаёт.
