# Ядро обсуждений и кандидатов задач r0.1

Пакет преобразует разрешённые нормализованные события в состояние обсуждения, вопросы, сводку и кандидата задачи. Он не является Telegram-ботом, анализатором естественного языка, системой согласования или исполнителем задач. Требуется независимая техническая проверка перед любым подключением.

## Запуск

Локальный Python 3.10+ под обычным пользователем, без сети и секретов. Установка пакетов, БД и служб не нужна. В каталоге должны находиться `facilitator_core.py` и `test_facilitator.py`.

```sh
python3 -I -B test_facilitator.py
python3 -I -B facilitator_core.py --demo
```

Первая команда выполняет синтетические тесты и печатает проверочные данные. Вторая печатает только синтетическую проекцию. Функция `discussion_fixture()` содержит воспроизводимую последовательность из 14 событий: проблему общего инструмента, понятие, утверждение о факте, цель, критерий, вариант, процедуру, две позиции, предварительное согласие, вопрос и явное разногласие. Четырнадцатое событие запрашивает синтез кандидатов.

## Типы и вход

`NormalizedEvent` соответствует `normalized_event`, `DiscussionState` соответствует `discussion_state`, `CandidateTask` соответствует `candidate_task`, `DecisionRecord` соответствует `decision_record`. Дополнительные неизменяемые типы: `SourceRef`, `RetentionPrivacy`, `Provenance`, `DiscussionItem`, `CandidateQuestion`, `CandidateSummary`. Это Python-типы с проверкой входов, не заявление о совместимости с внешним стандартом JSON Schema.

`normalized_event(bytes)` разбирает JSON строгого состава: `discussion_id`, `event_id`, `sequence`, `at_tick`, `action`, `category`, `derived_text`, `targets`, `disagreement_level`, `sources`, `policy`. Неизвестные поля и повторные JSON-ключи отклоняются. Полей raw update, raw text, Telegram user_id/username, токенов и команд исполнения нет.

Идентификаторы имеют вид `discussion_`, `event_`, `source_`, `candidate_` или `decision_` плюс 32 шестнадцатеричных символа. Они не должны вычисляться из audience identity. Источник содержит область обсуждения, непрозрачный идентификатор, SHA-256 разрешённой нормализованной версии и тип `synthetic_fixture` либо `normalized_projection`. Ядро проверяет форму и область ссылки, но не скачивает источник и не удостоверяет его подлинность. Это обязанность входного контура.

## Переходы

`apply_event(state, event)` возвращает новый неизменяемый объект. `observe` добавляет аналитический элемент; `retract` исключает указанный элемент из новой проекции; `synthesize` создаёт сводку, вопросы и, при наличии проблемы и цели, одного кандидата задачи. Повтор тех же event_id и байтов идемпотентен. Повтор event_id с другим содержимым отклоняется. Последовательность событий и логические отметки строго проверяются.

Разногласие не выводится из голосования или сходства текста: нормализованный вход должен явно указать минимум две существующие позиции/элемента и уровень facts/concepts/goals/criteria/means/procedure/other. Вложенные разногласия не поддерживаются. Без проблемы, цели или критерия формируются вопросы о недостающих данных, а не придуманные решения.

Утверждение о факте всегда помечено `reported_claim_not_verified_fact`. Предварительное согласие помечено `reported_preliminary_not_group_consensus`. Состояние группы остаётся `not_established`. Сводка группирует ссылки на элементы, не переписывает их в якобы установленную истину.

Кандидат содержит проблему, основание, ожидаемый результат, критерии, варианты, процедуру, нерешённые вопросы, происхождение и предполагаемого адресата `group_review_not_assigned`. Выбор первого упомянутого problem/goal в заголовке является детерминированным правилом черновика, не приоритетом группы; остальные элементы сохранены в основании.

## Приватность и сроки

`privacy_class`: `synthetic` либо `minimized_derived`. `retention_class`: `synthetic_snapshot` либо `memory_only`. Для `minimized_derived` разрешён только `memory_only`. Вся обработка происходит в памяти; модуль не пишет файлы, журналы или БД.

`expires_tick` задаётся вызывающей стороной. Это логическая отметка, не секунды и не выдуманное проектное время. Новое производное получает наиболее строгий класс и ближайший срок всех использованных входов. Повтор события срок не продлевает. `expire(state, tick)` создаёт новую проекцию без просроченного содержимого и зависимых кандидатов. Старый объект, Python-память, внешние копии, swap и файлы функция не стирает; реальные часы, расписание retention и удаление внешних копий относятся к будущему runtime-контракту. Деструктивных операций в ядре нет.

`snapshot()` возвращает байты только явно разрешённой синтетической проекции. Экспорт `minimized_derived` или `memory_only` закрыт. Восстановление произвольного snapshot как доверенного состояния не реализовано: состояние создаётся пустым и воспроизводится через проверенные события.

Метка `minimized_derived` не является доказательством очистки текста. Ядро не распознаёт персональные данные внутри строки. Нормализация, допустимость содержания и отсутствие идентификаторов должны быть проверены до вызова. Нельзя передавать сырой текст, просто переименовав поле в `derived_text`. Допуск настоящих данных и сохранение новых производных объектов не открываются этим пакетом.

## Решение человека не равно исполнению

`record_decision()` принимает только отдельную запись approve/reject/defer с точной версией кандидата, ревизией обсуждения и происхождением. По умолчанию вызов запрещён. Нужна внешняя доверенная функция проверки; поле moderator/operator само по себе полномочия не даёт. Синтетический verifier в тестах не подтверждает реальную личность и не заменяет будущую проверку человеческого допуска.

Записывается только решение о рассмотрении кандидата. Даже после approve сохраняются `candidate_only`, `executable=false`, `approved_for_execution=false` и отсутствие установленного согласия группы. Проектного task/dispatch/publish API в модуле нет. Изменение исходного обсуждения, отзыв или истечение срока аннулируют производные кандидаты и их текущие записи рассмотрения. Долговременный аудит решений не реализован; это сознательно ограниченный инкремент.

## Граница интеграции

`существующая Phase 1B → privacy/validation + normalization → это чистое ядро → отдельный human/group approval gate → отдельный dispatch/receipt`.

Ни один существующий Phase 1B файл не требуется менять для проверки этого пакета. Никакой новый runtime не подменяет её privilege/provisioning gate. Перед реальной интеграцией нужно независимо подтвердить соответствие aggregate-only, сформировать допустимую минимизированную проекцию, определить доверенную проверку решений и реальные сроки, затем отдельно разрешить точку подключения. Если это требует изменения Phase 1B, сначала вернуть точный blocker, а не исправлять транспорт из ядра.

## Проверяемые границы

Тесты проверяют повторяемость, ссылки, границы обсуждений, все уровни разногласий, кандидатов и недостающие данные, дубликаты и конфликты, сроки, закрытый экспорт, решение человека и отсутствие автоматического исполнения. Контролирующая обёртка устанавливается до импорта проверяемого модуля и запрещает сеть, запуск процессов, запись и недопустимое чтение. Проверки выполняются под UID 1000; запуск тестов под root запрещён.

Модуль рассчитан на доверенный Python-процесс и не защищает от изменения интерпретатора, `object.__setattr__`, подмены кода или намеренно ложного внешнего verifier. Frozen-типы и проверки не являются криптографической изоляцией.
