# Operational shard store r0.1 — offline synthetic candidate

Run **only** under a fresh local synthetic root: `python3 -B test_offline_store.py`. The test creates temporary roots and an explicit `.offline-synthetic-root` marker. No existing gateway/shard/project storage root is used. There is no network adapter, credential reader, GitHub publisher, host service, automatic writer transfer or deployment configuration. The database is a local SQLite test backend chosen to prove a transaction pattern; it is not a production backend appointment.

`offline_store.py` implements versioned canonical OperationalRecordV1 bytes, content-addressed immutable objects, namespace binding, PUT idempotency, full-prior-pointer CAS, operation-specific ledger/RESOLVE_OPERATION, writer fence high-water and fail-closed pointer/object/ledger validation. `SyntheticAdmission` is an injected test verdict. It cannot authenticate a real current writer, task, approved source or trust profile; the constructor is intentionally unadmitted by default. The externally governed trust root, epoch issuer, policy and backend remain UNKNOWN.

**Linearization:** SQLite `BEGIN IMMEDIATE` serializes concurrent CAS attempts. A CAS transaction compares the full prior pointer; verifies exact object, parent/generation and synthetic admission; updates fence high-water, pointer and operation request-digest/outcome/receipt identity; then commits as one transaction under WAL + `synchronous=FULL`. `APPLIED` is returned only after commit. Restart reads the pointer, fence and operation ledger; the pointer includes operation ID/request digest/receipt ID and fails integrity verification if its ledger is absent or conflicting. A simulated lost response after commit resolves to APPLIED from the ledger even if the current pointer later advances. This is process-crash evidence for this offline candidate, not power-loss/host durability or production atomicity proof.

PUT object and ledger are similarly transactional, but PUT does not make the object current. An orphan can exist if a PUT succeeds and CAS does not. Current-pointer and object divergence blocks. A Git anchor is a **synthetic comparison input** in this package, never fetched from GitHub by the implementation; `LOCAL_MATCH_ONLY` is not canonical verification. `RESOLVE_OPERATION` returns UNKNOWN if its local backend cannot be read. Duplicate operation IDs with different request digests fail closed.

`crash_worker.py` is a test subprocess that calls `os._exit(77)` at named stages. The test suite reopens the database and verifies all-or-none outcomes for pointer, fence and ledger at genesis and writer epoch rollover. It also verifies one winner under eight competing CAS calls. These tests use no real writer or shard authority.

Files: `SCHEMA.json`, `vectors.json` exact deterministic serialization/identity vectors, `test_offline_store.py`, `crash_worker.py`, `test.stdout.json`, `test.stderr.txt`, `evidence.json`, `MANIFEST.json`, `SHA256SUMS`. The top-level MANIFEST inventories all other final files (including SHA256SUMS) and excludes only itself to avoid recursion. The addressed KOD result records committed-byte readback after publication.

Limits: no durability claim (`CHECKPOINT_DURABLE` remains NOT_ESTABLISHED); no selected trust-root owner, storage operator/host, retention/RPO/RTO or production backend. No EOM-SHARD-PILOT-R01, memory-layering attempt 3, live WRITE/CAS or existing gateway mutation. Independent SIS and SHD implementation review is required before another gate.
