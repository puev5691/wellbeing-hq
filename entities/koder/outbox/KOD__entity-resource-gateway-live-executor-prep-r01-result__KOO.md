# КОДЕР → КОО: подготовка границы единичного исполнения r0.1

Результат: `PASS_ENTITY_RESOURCE_GATEWAY_LIVE_EXECUTOR_PREP_R01_READY_FOR_INDEPENDENT_VERIFY`.

Создан отдельный слой подготовки плана, проверки полномочий и однократной симуляции. КОО требуется подтвердить получение точных версий и назначить независимую техническую проверку. Реальный сетевой исполнитель не установлен, режим LIVE остаётся закрытым. Это результат подготовительного этапа, не разрешение и не подтверждение реального вызова.

## Что сделано

Слой использует принятый шлюз и его исходные EntityRequest/ResourceResult без изменения байтов. Отдельный интерфейс `LiveExecutorPort` задаёт будущую точку подключения; действующая реализация порта отсутствует. `prepare()` формирует проверяемый план. Единственный исполняемый путь `execute_once()` сейчас работает с заранее заданными тестовыми ответами.

`LIVE_EXECUTION_AUTHORITY` связывает конкретный источник допуска, исходную Сущность/роль/задачу/действующий экземпляр с правом записи, SHA-256 всего запроса и плана, provider/model, ссылку на credential, политику и окно действия. Полномочие не следует из названия объекта: обязателен отдельный доверенный verifier и совпадающий `VerifiedAdmission`. True вместо проверочного объекта недостаточно. Тестовые ссылки допуска не являются реальными решениями ОПЕРАТОРА.

По умолчанию `NO_LIVE` останавливает исполнение до порта. `SIMULATION` требует точного допуска. `LIVE` проверяет полномочие и переключатель OpenAI, затем всегда возвращает `BLOCKED_LIVE_ATTACHMENT_REQUIRED`, не вызывая порт. Произвольный объект с признаком сетевых возможностей не может включить сеть.

## Одна попытка и честные ограничения

Политика допускает конечный timeout 1–60 секунд, по умолчанию 30; ровно одну попытку; ноль автоматических повторов; ответ не более 65536 байт. Неизвестная модель, несовпадение плана, приватный payload, инструменты, внешняя отправка и повреждённый допуск отклоняются.

Тестовый OneShotLedger резервирует источник допуска до попытки. Успех, ошибка и timeout не возвращают право повтора. Блокировка действует в одном процессе с общим ledger; устойчивость к перезапуску не заявляется. Синтетический elapsed_seconds проверяет политику тайм-аута, но не измеряет и не прерывает реальный сетевой запрос.

Для будущего подключения нужны устойчивый атомарный реестр попыток, проверенный worker с жёстким сроком, пределом чтения и запретом неразрешённых перенаправлений, локальный resolver ссылки на credential, актуальный account/model/current-writer допуск и отдельное решение ровно на один вызов. Старый транспорт не объявляется автоматически достаточным для этих гарантий.

Принятый ResourceResult жёстко помечен `synthetic_no_network`, а исходный запрос запрещает внешнюю отправку. Реальный ответ нельзя подставить в него под видом симуляции. Будущий отдельный контракт должен честно описать реальное исполнение и узкий D0-egress, сохраняя полномочия requester. Этот пакет не меняет данные границы молча.

В получаемом тестовом ResourceResult сохраняются `project_acceptance=NOT_GRANTED`, прежний caller writer, отсутствие полномочий gateway/provider, `project_state_applied=false`, `external_dispatch_performed=false`, `routing_status=not_started`.
