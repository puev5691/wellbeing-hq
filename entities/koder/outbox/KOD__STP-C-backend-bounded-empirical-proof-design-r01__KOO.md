## Человеческий итог

Это проект одинаковой проверочной процедуры для четырёх возможных хранилищ журнала STP-C. Она проверит, переживает ли журнал конкуренцию, сбой и потерю ответа, и не выдаёт ли отсутствие связи или повреждение за отсутствие операции. Сейчас ни одно хранилище не запускалось, не сравнивалось по баллам и не выбрано.

## 1. Common test model and oracle

Every adapter presents the same logical `STPC_LEDGER_TEST_V1` operations: `reserve(request, expected_absent)`, `transition(operation_id, expected_state_revision, process_fence, next_state, evidence_identity)`, `claim(effect_auth_identity, idempotency_key, target, payload_digest, expected_revision, fence)`, `resolve(exact_request_or_operation_identity)`, `authoritative_readback(namespace)`, `integrity_check(namespace)`, `backup_restore`, `fence_successor` and `reset_disposable_root`. No implementation syntax is prescribed. `reserve` atomically binds `(namespace, request_id, request_digest)`, `(namespace, operation_id, intended_effect_identity, idempotency_key)` and nonce; a collision changes none of them. Transition and claim compare exact revision/fence and atomically persist successor state plus linked evidence. The model has `NEW, RESERVED, ADMITTED, SIGNED, VERIFIED, QUORUM_VALID, QUORUM_BLOCKED, PRE_EFFECT_VALID, AUTHORIZED, CLAIMED, COMMITTED, OUTCOME_UNKNOWN, REJECTED, CONFLICT, STALE, PENDING_RECONCILIATION`. The effect service is fake and cannot touch a real target.

The authoritative state projection includes `request_id, request_digest, operation_id, nonce_identity, state_revision, process_fence, effect_claim, idempotency_key, transition_identity, evidence_identity, terminal_result_identity, outcome_unknown_identity, reconciliation_evidence_identity`, exact target/payload and ordered immutable transition history. The expected projection for each test is computed from the frozen initial fixture and deterministic schedule by a supervisor-side oracle outside the adapter and worker capability. Candidate responses are compared to this projection, exact linked objects and fake-service invocation history. Never derive expected result from candidate logs. At most one incompatible reservation/claim/transition can win; lost response is resolved from authoritative exact state; partition/unavailability is not absence; a stale process never regains authority from restart. PASS requires all corresponding assertions; partial coverage is UNKNOWN, not PASS.

Canonical input profile, digest domains and oracle bytes must be pinned identically for every candidate in a later gate. Adapters may use different primitives but may not change the request, state machine, failure classifications, evidence semantics, test schedule or PASS oracle. The oracle is independent and read-only over exported evidence; the adapter cannot overwrite it. Proof-of-corruption must cover both backend product detection where required and application transition/evidence linkage; passing one layer does not silently prove the other.

## 2. Common fixture, barriers, classifications

Synthetic namespace `STPC-TEST-R01/<run_id>`, request `R1` digest `D1`, operation `O1`, nonce `N1`, effect `E1`, key `K1`, revision `0`, fence `F1`; successor values `R2/D2/O2/N2/E2/K2/F2` are distinct. All are fixed exact bytes in a future pinned fixture manifest; no real signatures, seats, credentials, project tasks or effects. `P1` and `P2` are separate synthetic client processes, `Q` is an independently launched authoritative-readback process, and the supervisor alone controls barriers/faults and private oracle. State `S0` is empty, `S1` is one reserved R1/O1/N1, `S2` is a valid pre-effect authorized O1 at a fixed revision, `S3` is CLAIMED O1, `S4` is COMMITTED O1 with fake receipt, `SU` is OUTCOME_UNKNOWN O1. Each row below names its starting fixture; no row inherits mutable state from a prior row except explicitly declared backup/restore subcase. A supervisor barrier pauses actors **before** compare/commit, **after** durable acknowledgment, **after** effect claim and **before/after** fake invocation as named. Barrier release order and fixed seed are evidence. Fault points marked `FP-*` must be adapter-visible and exact. Clock sleeps/timeouts may bound a run but never establish ordering or authority.

Classification `PASS` requires exact authoritative readback + integrity/chain check + independent oracle equality + relevant fake-service count; `FAIL` means a concrete forbidden outcome is observed; `UNKNOWN` means fault not injected/proven, readback ambiguous/unavailable, or evidence incomplete. Expected blocking outputs include `REQUEST_ID_COLLISION`, `OPERATION_ID_COLLISION`, `NONCE_REPLAY`, `IN_PROGRESS`, `IDEMPOTENT_REPLAY`, `EFFECT_OUTCOME_UNKNOWN`, `BLOCKED_EFFECT_EXECUTION`, `LEDGER_UNAVAILABLE`, `LEDGER_CONFLICT`, `LEDGER_CORRUPT`; `NOT_APPLIED` only from a proven current authoritative absence. Do not convert timeout to NOT_APPLIED or client error to failure of effect.

## 6. Reproducibility and adjudication

Run identity derives from candidate exact build + adapter version + test model/oracle + topology + configuration + fault method + fixture seed + schedule; a config or topology change creates a new proof identity. No sharing of a PASS across versions, products, settings, node count, durability/read mode or failure model. Reset verifies empty *new* namespace under authoritative read, fake journal cleared, old history preserved as immutable evidence; tests run in independent disposable roots. Barrier order is fixed, process IDs/fences and deterministic input derived from seed, no reliance on scheduler luck. A race test with no observed overlap is UNKNOWN and must be rerun only under a separately authorized execution gate. No automatic attempts/retries are granted by this design.

Supervisor computes independent oracle then compares readback and effect count; test worker/adapters cannot mutate oracle or result. An observed forbidden effect/state is FAIL. Missing injection proof, partial evidence, missing integrity readback or unresolved availability is UNKNOWN. Command exit code 0, restart, log line and timeout alone never PASS. `UNKNOWN` is not silently downgraded to PASS or FAIL. Read-only diagnostic observation remains distinct from authoritative current state and task authority. Recovered process is not recovered writer/seat/effect authority.
